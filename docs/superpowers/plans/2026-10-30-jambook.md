# Jambook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A self-hosted Rails songbook for house jams: one song list, one chord sheet per song, a host-pushed "now playing" with a synced room key, and a per-guest capo.

**Architecture:** One Rails 8.1 app on SQLite, 37signals style (Mick's `rails-toolkit` skills). A single `Room` row holds the live state and broadcasts a Turbo page refresh synchronously on every change; guest pages morph and a Stimulus controller re-renders the chord sheet in the browser with ChordSheetJS, applying the guest's own capo from `localStorage`. Access is deny-by-default host login (Rails 8 authentication generator) with guest-readable pages opted in behind a shared guest password (signed cookie).

**Tech Stack:** Ruby 4.0.2, Rails 8.1.4, SQLite, Turbo 8, Stimulus, importmap, ChordSheetJS 18.0.0, Solid Cable, Minitest with fixtures, Capybara/Selenium headless Chrome, Kamal 2.

**Spec:** `docs/superpowers/specs/2026-10-30-jambook-design.md`. Read §6.4 "Spike-proven gotchas" before Tasks 5–7.

## Global Constraints

- Repo at `~/Stack/Programmeren/jambook`, created with `rails new jambook` (CLI, defaults). App name in copy: "Jambook".
- Before each task read `rails-toolkit:rails-core` and the area skill the task names. Where this plan and a skill disagree, the plan wins only where it says why.
- Gems: `rails new` defaults, the dev-env standard, `csv` (Ruby 4 bundled gem), `strong_migrations` (as in booking-overview), `webmock` (test). Nothing else.
- ChordSheetJS `18.0.0`, vendored with `bin/importmap pin chordsheetjs@18.0.0`.
- Never commit copyrighted lyrics: fixtures and demo data use public-domain songs only (Amazing Grace, House of the Rising Sun, Scarborough Fair).
- Never commit personal data or server details: no song lists, UG exports, `config/deploy.<dest>.yml`, `.kamal/secrets.<dest>`, `fnox.toml`.
- Keys: `MusicKey::KEYS` majors `C Db D Eb E F F# G Ab A Bb B`, minors `Cm C#m Dm Ebm Em Fm F#m Gm G#m Am Bbm Bm`.
- Access: controllers require the host by default; guest-readable actions opt in with `allow_unauthenticated_access only:` and then pass `require_guest_access`. Guest cookie: signed, 30 days, `httponly`, `same_site: :lax`. Guest password form: `rate_limit to: 10, within: 3.minutes`.
- Broadcasts are synchronous (`broadcast_refresh`), never `broadcasts_refreshes` or `_later`.
- Layout `<head>` uses `turbo_refresh_method_tag :morph`, `turbo_refresh_scroll_tag :preserve` and `turbo_exempts_page_from_cache_tag` directly. Never the `turbo_refreshes_with` / `turbo_exempts_page_from_cache` helpers: they `provide :head` and silently vanish when called after `yield :head` (spec §6.4 gotcha 1).
- No custom controller actions: state changes are resources (`Songs::PlaysController#create`, `Rooms::KeysController#update`). Each action gets a one-line route comment (`# PATCH /room/key`).
- Bang method names only where a non-bang twin exists (`Room#play`, `Room#transpose`).
- Wrap every `localStorage` access in try/catch with an in-memory fallback.
- Tests: fixtures only, never edit an existing fixture (add a new one); one behaviour per test, at most 4 assertions, sentence names (`test "guests need the password"`). Shared helpers in `test/test_helpers/`.
- Test runs: one file `t <file>`; full suite = `t` **and** `t test/system/*_test.rb` (`t` alone skips system tests; file arguments run with 1 worker, as system tests need).
- Work in a worktree at `.worktrees/build` (branch `build`) after Task 1; commit per task; merge to `main` after Task 12. Task 13's deploy needs Mick's explicit go.
- Keep `.claude/current_plan.md` pointing at this plan with the last finished task (multi-session-plans).

## Review Focus

1. **A sheet with no chords or no key** (pasted lyrics, bad UG text): the page shows the text, says "Key unknown" and doesn't throw. Test: Task 6 `"sheet without a key shows its text"`.
2. **Fresh install, empty room**: Live shows "Nothing playing yet" for guests and a "Pick a song" link for the host. Test: Task 5 `"empty room tells guests nothing is playing"`.
3. **Host deletes the song that is playing**: the room empties, guests get a refresh, nothing 500s. Test: Task 5 `"deleting the playing song empties the room and refreshes guests"`.
4. **A CSV saved from Excel** (UTF-8 BOM, CRLF, blank rows, stray spaces): imports cleanly. Test: Task 10 `"Excel CSV imports cleanly"`.
5. **Storage blocked** (private browsing, `localStorage` throws): capo buttons still work for the page's lifetime. Test: Task 6 `"capo works when storage is blocked"`.
